# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Overview

This project is a reinforcement-learning bridge for Balatro. It does not automate
shop, joker, tarot, planet, booster, skip, or other deck-building decisions. The
modeled scope is in-blind card selection only: choose whether to play or discard
cards from the current hand to maximize chip score.

The system has two halves:

- `bridge/`: Lua code injected into Balatro with Lovely Injector. It watches
  Balatro game state, writes `state.json`, polls `command.json`, selects cards,
  and calls Balatro's play/discard functions.
- `env/`: Python Gymnasium environment. It reads `bridge/state.json`, encodes the
  raw state into a fixed vector, writes `bridge/command.json`, and computes
  shaped rewards.

## Setup And Run Commands

Use a virtual environment, then install dependencies:

```bash
pip install -r requirements.txt
```

Run the random-policy smoke script while Balatro is running at a hand-selection
screen and the Lua bridge is writing state:

```bash
python run_env_example.py
```

Record expert data interactively:

```bash
python record_expert.py --output expert_data.jsonl
```

Train and run the behavioral-cloning policy:

```bash
python train_bc.py --data expert_data.jsonl --model-out models/balatro_bc.zip
python play_bc.py --model models/balatro_bc.zip
```

Run offline tests:

```bash
python -m unittest discover -s tests -v
```

Both Python entry points default to the repo-local `bridge/` directory. Override
that path with PowerShell:

```powershell
$env:BALATRO_BRIDGE_DIR = "F:\path\to\bridge"
```

or with `cmd.exe`:

```cmd
set BALATRO_BRIDGE_DIR=F:\path\to\bridge
```

On non-Windows shells, use the equivalent environment-variable syntax.

## Balatro And Lovely Runtime Notes

The Lua bridge is meant to run inside the Steam/Love2D Balatro process through
Lovely Injector. The README describes using the Steam launch option `--dump-all`
to inspect dumped game Lua files, then symlinking this repo's `bridge/` folder
into Balatro's Lovely Mods directory.

Important: `bridge/main.lua` currently has a hard-coded Windows bridge path:

```lua
local bridge_dir = "F:\\Github\\Balatro-RL\\bridge"
```

If this repo moves, update that path or ensure the symlink/runtime path still
matches. The Python side can be redirected with `BALATRO_BRIDGE_DIR`, but the Lua
side will keep writing wherever `bridge_dir` points.

After editing `bridge/main.lua`, restart Balatro so Lovely reloads the bridge.

## File Protocol

Game to Python: `bridge/state.json`

The full state emitted by `bridge/main.lua` includes:

- `state_version`: Structured bridge schema version, currently `2`.
- `seq`: Monotonic integer incremented on every state write.
- `phase`: Numeric `G.STATE`.
- `money`, `chips`, `blind_chips`, `hands_left`, `discards_left`.
- `hand`: Array of cards with 1-based `index`, `value`, and `suit`.
- `hand_levels`: Per-hand-type metadata from `G.GAME.hands`, when available.
- `last_hand_played`: Last scored hand name, when available.
- `round_result`: Empty during play, then `won` or `lost` on a terminal
  transition.
- `run`: Seed, ante, round, stake, deck counts, and round usage counters.
- `blind`: Blind key/name/type, boss/disabled flags, and debuff configuration.
- `jokers`, `consumables`: Ordered inventory snapshots with identity, edition,
  debuff, price, and primitive ability state.
- `hand` cards also include center/enhancement key, seal, edition, debuff,
  facing, forced-selection, and played-this-ante state.

The bridge may write a minimal state with `hand: []` during transitions away from
`SELECTING_HAND`. These snapshots retain score/resource fields.
`BalatroEnv` skips non-terminal transitions and accepts terminal ones.

Python to game: `bridge/command.json`

```json
{"action":"play","cards":[1,2,3]}
```

Outside hand selection, an opt-in environment can send:

```json
{"action":"advance","cards":[]}
```

The bridge then cashes out, leaves the shop without purchases, or selects the
next blind. After game over it opens New Run setup, selects Red Deck, presses
Play, and selects the Small Blind until a playable hand exists.

`action` must be `play` or `discard`. `cards` are 1-based hand indices. The
Python env clamps invalid indices and caps play actions to 5 cards. The Lua
bridge also validates that Balatro is in `G.STATES.SELECTING_HAND`, that a hand
exists, that each card index is in range, and that hands/discards remain.
Python converts discard requests to play when no discards remain.

The `seq` field is critical. `BalatroEnv.step()` waits for `state.json` with
`seq > last_seq`; without this, the agent can silently train on stale states.

## Observation And Action Layout

Source of truth:

- `env/balatro_env.py`: `NUM_CARD_SLOTS`, `ACTION_DIM`, legacy `OBS_DIM`,
  `MAX_PLAY_CARDS`, reward parameters.
- `env/feature_encoder.py`: Versioned layouts, dimensions, and feature order.

Observation v1 is frozen at 60 values for existing datasets/models:

- 6 scalar fields: phase, money, chips, blind target, hands left, discards left.
- 8 card slots times 3 features: present flag, normalized value, normalized suit.
- 10 hand types times 3 features: normalized level, chips, mult.

Observation v2 is 915 values and uses only normally visible information:

- Run resources, blind identity/debuff, target progress, and poker summaries.
- Enriched per-card features, hand levels, jokers, and consumables.
- The run seed is stored in raw/log metadata but intentionally excluded from
  policy observations.

`BalatroEnv` defaults to v1 for compatibility. New recorder output files default
to v2; existing files are detected by their observation length. Training infers
the version from the dataset, playback infers it from the model, and mixed
dimensions in one dataset are rejected.

Current action dimension is 9:

- `action[0]`: `0` for play, `1` for discard.
- `action[1]` through `action[8]`: binary card mask for 1-based hand indices.

When changing this layout, update `BalatroEnv`, `feature_encoder`, both scripts,
and README docs together.

## Reward And Episode Behavior

`BalatroEnv` uses shaped rewards:

- Chip delta times `reward_scale`.
- Discard penalty for discard actions.
- Optional hand-type bonus once per scored play using `last_hand_played` or
  `last_hand_type`.
- Win bonus when `chips >= blind_chips`.
- Loss penalty when the bridge reports `round_result: "lost"`.

`step()` returns `terminated=True` when `round_result` is `won` or `lost`, and
uses `truncated=True` on timeout or missing post-action state.

## Development Guidelines

- Keep the Lua/Python JSON contract synchronized. Any bridge field rename usually
  needs matching changes in `feature_encoder.py`, `balatro_env.py`, and docs.
- Preserve the 1-based card indexing at the file protocol boundary. Convert only
  inside Python helpers where needed.
- Treat `state.json` and `command.json` as runtime files, not fixtures.
- Do not commit `.venv/`, Python caches, `expert_data.jsonl`, or bridge runtime
  outputs.
- Prefer small, direct changes. This repo has no package metadata or formatter
  config; tests use `unittest` under `tests/`.
- If adding tests, start with pure Python tests around `encode_state()`,
  `parse_action_string()`, and `_action_to_command()` because they do not require
  Balatro to be running.
- If modifying Balatro runtime behavior, manually smoke-test with Balatro open at
  `SELECTING_HAND` and watch that `state.json` gets a fresh `seq` after every
  action.
- Keep v1 byte-for-byte backward-compatible while structured state evolves.
  New expert records store `raw_state` so later encoders can regenerate
  features. Never add the run seed to a policy observation.

## Known Quirks

- `README.md` contains mojibake in some arrows/box-drawing characters. Fixing the
  encoding is a docs cleanup task, not required for normal runtime changes.
- `bridge/state.json` may exist locally even though it is ignored; its contents
  are just the last runtime snapshot.
- The Lua bridge builds JSON strings manually. If adding fields, escape strings
  with `json_escape()` and keep numeric conversions defensive.
